在 PowerShell 中进入仓库、安装当前代码，然后设置两个不同的 token。token 的内容由你自己决定；可以先运行下面的生成命令两次。

In PowerShell, enter the repository, install the checkout, and configure two different tokens. You choose their values; run the generator below twice if needed.

生成随机 token（运行两次）Generate a random token (run twice)

安装并启动Install and start
cd C:\path\to\coding-tools-mcp
python -m pip install -e .
$env:CODING_TOOLS_MCP_AUTH_TOKEN = "<普通用户 token>"
$env:CODING_TOOLS_MCP_ADMIN_TOKEN = "<另一个 Admin token>"

把最后一行换成：python -m coding_tools_mcp.server --workspace "G:\path\to\your\project" --host 127.0.0.1 --port 8765。

Command not found?

Replace the final line with python -m coding_tools_mcp.server --workspace "G:\path\to\your\project" --host 127.0.0.1 --port 8765.

看到终端输出 coding-tools-mcp listening on http://127.0.0.1:8765/mcp 后，保持这个窗口运行。用 Ctrl+C 停止服务。

Keep the terminal open after it reports coding-tools-mcp listening on http://127.0.0.1:8765/mcp. Press Ctrl+C to stop it.

2. /app 处的“密码”在哪里设置？2. Where is the /app “password” configured?

最简单的答案

Short answer

/app 输入的是上面 PowerShell 中的 CODING_TOOLS_MCP_AUTH_TOKEN 值，不是一个单独的 App 密码。

/app expects the value of CODING_TOOLS_MCP_AUTH_TOKEN from the startup shell. It is not a separate App password.

为什么 WebUI 中没有设置项？

Why is it absent from the WebUI?

这是服务启动时的认证边界。Admin WebUI 必须先通过认证才能管理服务，因此不能用它来创建当前进程自己的登录 token。修改环境变量后需要重启服务。

This is a startup authentication boundary. The Admin WebUI must already be authenticated before managing the service, so it cannot bootstrap the current process's own login token. Restart after changing the environment variable.

  1. 启动前设置 $env:CODING_TOOLS_MCP_AUTH_TOKEN = "你的随机 token"。
  2. 打开 /app，点击“连接身份”。
  3. 把同一个 token 粘贴到输入框。
  1. Before startup, set $env:CODING_TOOLS_MCP_AUTH_TOKEN = "your random token".
  2. Open /app and choose **Connect identity**.
  3. Paste the same token into the field.
不要填 Admin token。 CODING_TOOLS_MCP_ADMIN_TOKEN 只用于 /admin，故意不能登录 /app。
Do not enter the Admin token. CODING_TOOLS_MCP_ADMIN_TOKEN is for /admin only and intentionally cannot sign in to /app.

高级部署也可以在 OAuth 模式下输入 OAuth access token。本机 loopback 若完全未配置认证，服务会显示 no auth configured；这只适合受信任的本机环境，不要公开暴露。

Advanced deployments may enter an OAuth access token instead. A loopback server started without credentials reports no auth configured; use that only in a trusted local environment and never expose it publicly.

4. Agent 工作台基本流程4. Agent workbench workflow

可选工作台，不是 GPT 网页

Optional workbench, not a GPT webpage

它通过 Codex App Server 驱动 Codex Agent；不提供 ChatGPT/GPT 网页聊天服务。

It drives a Codex Agent through Codex App Server; it does not provide a ChatGPT/GPT web chat service.

执行主机前提

Execution-host prerequisite

执行主机必须安装 Codex CLI，并已完成登录（例如先运行 codex login）。Runner Workspace 必须在对应 Runner 主机完成。

The execution host must have Codex CLI installed and signed in (for example, run codex login). A Runner Workspace requires this on its Runner host.

三套不同凭据

Three credential sets

App bearer/OAuth access token 用于 /app；Admin token 只在 /admin 创建服务器端 Session 时使用；Codex 登录凭据由执行主机上的 Codex CLI 管理。三者不能互换。

The App bearer/OAuth access token is for /app; the Admin token is used only to create a server-side Session for /admin; Codex CLI credentials are managed on the execution host. They are not interchangeable.

两部分持久化

Two-part persistence

Coding Tools MCP SQLite 保存 Agent Session 元数据，Codex thread store 保存模型 thread 与对话连续性；两者共同完成恢复。

Coding Tools MCP SQLite stores Agent Session metadata, while the Codex thread store keeps model-thread and conversation continuity; recovery depends on both.

  1. 连接身份并选择 Workspace。
  2. 创建 Agent Session，填写任务说明。
  3. 发送 Turn；遇到审批请求时检查命令再决定。
  4. 运行 Validation 获取结构化证据。
  5. 交接前查看 Handoff 中的分支、指纹、job 和验证结果。
  1. Connect the identity and select a Workspace.
  2. Create an Agent Session and enter task instructions.
  3. Send a turn; inspect commands before deciding approval requests.
  4. Run Validation for structured evidence.
  5. Before handoff, inspect the branch, fingerprint, jobs, and validation result.

Session 会持久化。页面刷新或断线后重新选择原 Session，不要盲目重复提交可能已经执行的写操作。

Sessions are durable. After refresh or disconnect, reselect the original Session instead of blindly resubmitting a write that may already have run.

5. 连接远程 Runner5. Connect a remote Runner

Runner credential 由 Admin API 签发，与 App token、Admin token 都不同。生产连接必须使用 wss://。

A Runner credential is issued by the Admin API and is separate from both App and Admin tokens. Production connections must use wss://.

Runner
$env:CODING_TOOLS_MCP_RUNNER_CREDENTIAL = "<Runner credential>"
coding-tools-mcp-runner `
  --server "wss://control.example/runner/ws" `
  --runner-id "lab-win-01" `
  --workspace "chem-project=G:\Research\chem-project"

6. 常见问题6. Troubleshooting

/app 显示 401/app returns 401

确认输入的是当前服务进程启动时读取的 CODING_TOOLS_MCP_AUTH_TOKEN，不是 Admin token。修改环境变量后重启服务。

Enter the CODING_TOOLS_MCP_AUTH_TOKEN read by the current server process, not the Admin token. Restart after changing it.

端口打不开The port does not open

确认启动终端仍在运行，并以终端实际输出的地址为准。本文命令显式使用 8765。

Keep the startup terminal running and use the address it reports. This Wiki explicitly uses port 8765.

Runner unavailableRunner unavailable

恢复原 Runner 及其 credential。系统不会把远程 Workspace 偷偷切换成本地路径。

Reconnect the original Runner with its credential. A remote Workspace never silently falls back to a local path.

7. 安全清单7. Security checklist

  • 普通 bearer/OAuth、Admin token、Runner credential、Codex CLI 登录凭据彼此分开。
  • Admin token 只用于 POST /admin/api/session 一次性交换；不要保存到 Web Storage、URL 或可读 Cookie。
  • 不要把 token 放进 URL、二维码、Git、截图或聊天记录。
  • 公网只使用 HTTPS/WSS 和认证 tunnel。
  • 不要公开暴露 noauth 服务。
  • Keep ordinary bearer/OAuth, Admin token, Runner credentials, and Codex CLI credentials separate.
  • Use the Admin token only for the one-time POST /admin/api/session exchange; never store it in Web Storage, URLs, or script-readable cookies.
  • Keep tokens out of URLs, QR codes, Git, screenshots, and chats.
  • Use HTTPS/WSS and an authenticated tunnel for public access.
  • Never expose a no-auth service publicly.
